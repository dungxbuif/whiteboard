# Collaboration v2 release handoff

## Critical anti-patterns

| Pattern | Description | Severity | Prevention mechanism |
| --- | --- | --- | --- |
| Image-only rollback after promotion | A promoted v2 scene has durable Yjs history that old images cannot safely own. | blocking | Use the replacement-scene recovery runbook or a verified database restore; never switch only application images for promoted scenes. |
| Treating historical Socket.IO plans as current | `.planning/phases/04-*` predates the approved v2 design and names the retired transport. | advisory | Use `docs/superpowers/plans/2026-10-16-collaboration-v2.md`, architecture docs and the release checklist as authority. |
| Parallel renderer release gates | Simultaneous heavy builds obscured a real Chromium two-line startup-file race. The race is fixed and covered, but parallel runs make release evidence harder to attribute. | advisory | Run final repository, MCP renderer and production build gates sequentially and retain their exit results. |
