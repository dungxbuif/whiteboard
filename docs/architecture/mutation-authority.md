## Private decision protocol

Go owns policy. Node obtains a decision **before** opening its append transaction. Private Go listener (`AUTHORITY_LISTEN_ADDR`, default loopback `127.0.0.1:8081`) exposes only `POST /internal/authority/decisions`. It must never be reverse-proxied publicly. `Authorization: Bearer <AUTHORITY_SERVICE_SECRET>` uses a dedicated >=32-byte secret distinct from login, room and decision secrets. `MUTATION_GRANT_SECRET` is a separate >=32-byte HS256 signing secret shared only with the trusted collab service.

Request JSON: `{ "roomToken": "...", "workspaceId": "UUID", "sceneId": "UUID", "action": "scene:update", "requestId": "opaque ID", "payloadHash": "lowercase 64-character SHA256 hex", "expectedSequence": "0" }`. Actions: `scene:update` (binary Yjs update), `scene:command` (internal JSON command), and `scene:read` (fresh room-read admission). `expectedSequence` is an optional canonical unsigned decimal int64 string; a supplied precondition must be checked by Node. Request IDs are 1–128 printable ASCII characters. The Go handler derives principal solely from a valid A3 room token, checks exact workspace/scene scope and expiry, then checks current access inside `WithWorkspaceLock`. Unknown principal kinds and agent principals fail closed in A4. D1 integration must call an explicit current scope check (`scene:read` for read, `scene:write` for update/command) before enabling agent grants; a write-only key must not imply read scope.

Success JSON: `{ "token": "<HS256 JWT>", "expiresAt": "RFC3339 timestamp" }`. JWT claims: `iss=whiteboard-api`, `aud=whiteboard-mutation`, `purpose=mutation-decision`, `sub=principalId`, `jti=random UUID`, numeric `iat`, numeric `exp`, `workspaceId`, `sceneId`, `principalType`, `principalId`, `grantId`, `grantVersion` (public only), `access=view|edit`, `aclVersion` (decimal string), `action`, `requestId`, `payloadHash`, and optional `expectedSequence`. Lifetime is at most 5 seconds and capped by parent room expiry and current public-link expiry. No clock-skew grace. A decision error or failed transaction produces no grant; HTTP 401 invalid credentials, 403/404 inaccessible, 400 malformed, 503 authority/storage failure.

## Bytes, lock order and append

Hash exactly the bytes Node will validate/apply: for `scene:update`, the decoded Yjs update bytes (excluding transport frame/version/channel/request ID); for `scene:command`, UTF-8 bytes of the original command JSON serialized once by the sender. **No JSON canonicalization, key sorting, whitespace removal, or parse/re-serialize is permitted between hashing and verification.** Transport commands as base64 bytes alongside a signed grant; decode once, verify SHA256, then parse. Semantically equivalent JSON with different bytes is a different payload. For `scene:read`, hash the empty byte string (`e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`). Never trust a caller-provided hash without recomputing it from actual payload bytes.

Node verifies HS256 algorithm, issuer, sole audience, purpose, issuance/lifetime and all bindings. It then begins a transaction, `SELECT id,acl_version FROM workspaces WHERE id=$1 AND deleted_at IS NULL FOR UPDATE`, checks `aclVersion` exact decimal equality and expiry **again after acquiring the lock**, then locks scene/document and checks scene scope/deletion and expected sequence. Validate/recheck expiry immediately before durable append; retain workspace lock through commit. ACL revocation uses the same workspace lock. If revocation commits first, a stale grant cannot append. If append obtains the lock first, revocation waits and linearizes afterward. Never make a Go authority request while holding this lock. Stale version/expiry means abort and obtain a fresh decision outside the transaction. Permission must still be current before returning any dedup receipt. Durable request ID uniqueness binds scene + principal + payload hash, with receipt retention through compaction. No optimistic append on authority failure.

## Assets and TURN

`POST /api/v1/scenes/{id}/assets/upload-capability` accepts login JWT + workspace header or scene-session/room token. Public aliases `/api/v1/public/scenes/{id}/assets/presign-upload` and `/presign-view` accept scoped tokens only. GET `/api/v1/realtime/config` requires a scoped token. Asset upload/view requests carry verified scene-session identity or authenticated login identity and use current scene authorization inside the workspace transaction. Upload requires edit; view requires view. Upload URL lifetime is <=60 seconds and <= parent credential expiry. Current link expiry also caps public uploads. Public uploads store `uploaded_by=NULL`; audit actor is the guest principal, never a fabricated user UUID. Metadata is scoped by workspace **and** scene. Image types are PNG/JPEG/GIF/WebP, 1 byte–10 MiB per file, 1–100 unique file IDs per batch; dimensions and optional checksum are validated. S3 PUT signatures bind exact Content-Length and Content-Type. Response returns Content-Type; client must send it and a Blob of the declared size. Browsers automatically supply Content-Length; clients must not set this forbidden header manually. Existing SVG/AVIF references remain readable. Already-issued object-store URLs remain valid until expiry; revocation prevents new grants but cannot recall existing URLs.

TURN REST credentials are minted only after scene access, with lifetime capped by the parent session and current link expiry; the shared TURN secret never appears in responses. Configured TURN requires a REST secret, with no static-password fallback on scene-scoped routes.
