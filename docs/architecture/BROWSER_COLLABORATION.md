# B3 browser collaboration detail design

Status: implemented; local verification recorded in the B3 task report, release acceptance pending. Authorized by the approved collaboration-v2 programme; controller owns commits and release records. Links: [programme](../superpowers/plans/2026-10-16-collaboration-v2.md), [phase](../work/phases/PHASE-COLLAB-V2.md).

The browser uses the B2 WebSocket contract (auth/refresh, ready, bounded sync_chunk, channel 3 updates, ack), nested Y.Map element fields and ordered ID arrays. CollabProvider owns one document and transport per principal/workspace/scene. Editing is disabled until fresh ready authority and complete synchronization. Only local origin updates enter IndexedDB; writes are persisted before send. Acknowledgements are accepted only from the current admitted connection and exact principal/workspace/scene/documentId scope plus request ID. Replay loads retained updates after server sync; merge never replaces the queue. Revoke, account switch, epoch mismatch, quota/storage failure and 64 MiB history limit preserve recovery and disable transmission as appropriate. Pending edits are exportable; different identities are never silently reassigned.

Native renderer callbacks are diffed by field against the last rendered content. Remote transactions update the native canvas with history capture disabled and do not echo. Yjs UndoManager tracks only local human operations; AI operations are separate atomic origins and not advertised as blindly undoable. Native undo is intercepted/hidden in v2; explicit local undo/redo uses the Yjs manager. AI additions and presentation reorder enter the same adapter; scene-store HTTP saves are fenced while v2 owns a scene.

Blobs are retained durably before upload. Upload capability requests use sceneId plus assets[], actual Blob.size, returned Content-Type, and browser-managed Content-Length. Only successful PUTs produce assetId references. Failed uploads retain bytes and retry from explicit retry/reconnect; view requests include sceneId. Credentials remain outside Yjs. Public scene sessions are retained in sessionStorage for the same tab/link only; expiry/revocation clears the credential, never the IndexedDB queue, and recovery is explicitly visible when identity changes.

Ruling: v1 HTTP fallback requires explicit COLLAB_DISABLED or PROMOTION_REQUIRED plus freshly fetched writerMode=v1, and is forbidden after v2 admission. A racing 409 COLLAB_REQUIRED preserves recovery and switches back to v2 admission. Public legacy scenes remain read-only. Connection failures never select the legacy writer. B4 receives transport subscribe/send hooks for presence/voice; no new voice protocol is invented here.

Verification: unit RED→GREEN for convergence/bindings/no-echo, true IndexedDB durable scope and matching ACK, revoked/reload replay, undo preserving remote edits, AI and presentation writers, upload failures and byte contract. Build and full frontend suite; existing dashboard Playwright tests plus actual browser/Node/PostgreSQL integration where fixture permits. Mock socket tests are protocol-unit proof only. Native Excalidraw/dashboard styles remain unchanged. Final report records exact commands and limitations.

Affected docs: human collaboration guide, architecture B3 section, public Markdown collaboration reference. Controller appends coordinated operations note and central context/backlog/validation/changelog. No schema or public Go API change is required.

## B3 review fix round 1 — intended lifecycle behavior

P1: an upload belongs to one active canvas/controller lifetime and captured principal/workspace/scene/document scope. Every continuation after asynchronous reads, capability/PUT, save and durability waits must recheck that lifetime and scope before writing or deleting recovery. Stopping transport revokes edit eligibility synchronously, including legacy mode. A completed PUT after navigation must leave Blob/draft recovery for reopening; it must not mutate a detached Yjs document. Reopening retries from the retained namespace under fresh authority.

P2: flush reserves the connection generation's single send slot before awaiting durable state or IndexedDB. Only that reservation can send or release its slot; an older generation cannot clear a new generation's reservation. A matching ACK cancels the only owned15s deadline. Overlapping explicit/scheduled flush, ACK and advancing past the deadline must leave one transmitted frame and a healthy socket.

Verification: focused transport overlap/stop tests, pending-PUT teardown/reopen regression for v2 and legacy eligibility, production build and native browser regression. No server/protocol/dependency changes. B4 frontend remains held through clean review.

Fix reconciliation: transport stop now synchronously clears edit eligibility and exposes isActive(). The native upload continuation checks mounted lifetime, active controller identity, captured principal/ref/document scope and current write mode after asynchronous boundaries, including capability completion and PUT completion. Cleanup preserves recovery whenever ownership changes. Legacy save and cleanup paths use the same lifetime checks. Flush owns a generation-specific reservation before awaiting durability/IndexedDB, revalidates ownership immediately before send, and its timeout can close only while that exact request remains outstanding. V2 and legacy mounted-wrapper regressions prove held-PUT completion after teardown retains recovery and reopening commits it; the send regression overlaps timer and explicit flush, ACKs, advances16s and verifies one frame plus an open socket.

## B3 review fix round 2 — intended draft ordering

Native image callbacks reserve a monotonically increasing durable revision in the exact principal/workspace/scene/document scope before converting data URLs. Reservation atomically updates that scope's latest recovery draft and existing Blob rows. Late converted bytes remain recoverable, but attach the newest durable draft for their original scope; they never read a new controller's mutable draft ref. This orders callbacks across unmount and same-scope reopening, not merely within one React mount. Confirmed cleanup compares its revision and atomically removes only that revision's recovery; retained revision tombstones prevent old conversions from resurrecting completed drafts. Existing IndexedDB stores gain optional fields, without a new store or database version. Verification covers newer-first/unmount/older-last, same-scope newer controller, different-principal scope isolation, exact retained bytes and reopened content, while preserving fix1 upload/flush guards.

Fix2 reconciliation: reserveImageDraft updates the durable revision/draft and existing Blob rows in one transaction; putImageBlob keeps bytes under the original scope and attaches its latest durable draft; completeImageDraft conditionally clears matching-revision recovery in one transaction and retains a revision marker. Old-format retained Blob drafts receive a revision before upload. Four mounted callback tests preserve exact bytes and reopened x values, including initial conversion finishing after teardown, and a separate store-reopen test rejects stale cleanup/resurrection. Collaboration32/10files and production build pass; fix1 lifetime/flush regressions remain green.
