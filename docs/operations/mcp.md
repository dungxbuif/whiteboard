# MCP rendering operations

D4 is implemented and locally verified on merged master. Production remains
v1 until the release gate. See the [Collaboration v2 programme](../superpowers/plans/2026-10-16-collaboration-v2.md).

## Configuration and build

Build from `src` in order: `npm ci`, `npm run build --workspace ./packages/collab-contracts`, `npm run build --workspace ./packages/diagram-kit`, then `npm run build --workspace ./mcp`. The last command emits Node ESM into `mcp/dist` and the Vite browser bundle plus verified fonts into `mcp/render-dist`. Generated output is ignored. Playwright 1.60.0 Chromium must be installed in the runtime; the renderer image uses the matching upstream image and `PLAYWRIGHT_BROWSERS_PATH=/ms-playwright`.

The HTTP adapter requires `WHITEBOARD_API_URL` (Go origin, which may be private), `WHITEBOARD_PUBLIC_URL` (public frontend origin serving `/w` and `/mcp`), `MCP_AUDIT_PATH`, and an explicit `MCP_ALLOWED_ORIGINS` allowlist. `MCP_BIND_HOST` defaults to loopback; container wiring uses `0.0.0.0`. `PORT` defaults to 3002. Origins must be HTTP(S) without credentials, query, fragment or a path; remote origins require HTTPS, while loopback HTTP is permitted for local development. There is no private-API fallback for public scene/artifact URLs. See `src/mcp/.env.example`.

Stdio clients require their own scoped `WHITEBOARD_AGENT_KEY`, both URL variables pointing to the public frontend origin when it proxies Go (or an explicitly configured separate HTTPS API origin), and a local audit path. `export_scene` forwards to authenticated `POST /mcp/exports` on that configured public origin; it does not expose a local-cache URL. Native compilation/generation still runs in the local stdio process and requires installed Playwright Chromium; only export artifacts are delegated to the HTTP service. Internal bridge/grant secrets stay on the server. HTTP redirects are refused, ordinary API responses are bounded to 256 KiB, export projection/asset responses to 26 MiB, and remote export responses to 256 KiB. Individual Go requests have 10-second deadlines; the remote export request has a 30-second deadline.

## Process and resource boundary

The renderer accepts validated native scene JSON or restricted native Mermaid, never a caller-supplied URL. For each job the parent creates a private temporary directory, directly spawns the pinned Chromium executable and owns its process handle before startup can stall. Chromium uses a generated loopback-only CDP port and a profile inside that directory. The render child receives that endpoint, connects with Playwright and closes Chromium through CDP on ordinary completion. Its 256 MiB Node heap and sanitized environment contain only PATH, private HOME/TMP locations, NODE_ENV and the browser installation path; application secrets are omitted.

A single external 10-second watchdog covers browser startup, compilation/rendering and normal shutdown. It SIGKILLs all owned process groups when work exceeds that deadline. Normal/error cleanup requests graceful termination, escalates after at most 250ms, reaps the child processes and waits up to one second for descendant groups to disappear. The service does not release its busy slot until those processes are gone and its exact job directory is removed. Reaping/filesystem cleanup can finish just after the deadline; failed cleanup leaves that worker unavailable until service restart, rather than admitting more jobs over leaked resources. No global temporary-directory scan or deletion occurs.

The compilation worker and export worker each permit one active job with no queue. Deploy with a nonroot user, init/reaping, container memory/PID bounds, writable temporary storage and a persistent private audit volume. Direct Chromium headless/CDP flags are pinned and must pass the final nonroot image smoke after browser upgrades. The launch retains `--no-sandbox` and does not claim OS browser sandbox isolation; the exact resource allowlist and CSP remain the verified network boundary.

Limits: 50,000 source/input characters; 500 nodes, 1,000 connectors and 3,000 total native elements including labels; 25 MiB scene JSON; 100 referenced assets; 10 MiB per stored raster; 20 MiB combined raster bytes; 4,096 pixels on each image/export axis; 20 MiB final artifact. JSON exports remain editable and embed authorized raster bytes. Rendering can fail explicitly when inline fonts make an SVG exceed the artifact limit. Legacy SVG/AVIF asset references are unsupported; current uploads are PNG/JPEG/GIF/WebP. Missing, malformed, mismatched or oversized assets fail rather than disappear silently.

Browser resources come from an exact local bundle allowlist at a fixed synthetic origin. CSP and Playwright routing deny external, metadata, loopback and file resources, service workers and WebSockets. Caller URLs are never fetched. The font manifest pins 234 WOFF2 files from Excalidraw 0.18.1 by SHA-256; the build verifies hashes and copies corresponding license notices. Native generation cannot emit images. PNG is an explicit export format. The official browser converter preserves IDs and deterministic reconciliation metadata; measured text is fitted within the compiler's original label box to retain multiline/Unicode labels.

## Authority, downloads and audit

`export_scene({sceneRef:{workspaceId,sceneId},format:"json"|"svg"|"png"})` returns `{id,mimeType,expiresAt,url,revision}`. Revision is a decimal string, preserving values above JavaScript's safe integer range. Export projection, asset retrieval and every download use independent current Go `scene:export` authority. `scene:read` alone is insufficient, and export-only keys can export without receiving the read capability. Rendering reads durable acknowledged content. Authority is rechecked after processing before a grant is issued; later scene edits do not change that artifact's captured revision.

The HTTP adapter owns a private memory cache, capped at 16 artifacts/64 MiB. Grants expire within five minutes; restart/cache loss makes existing URLs unavailable, and no artifact is persisted to storage. URLs are not bearer credentials: `GET /mcp/artifacts/{id}` requires the same agent bearer key, current ownership/membership, target restriction and export scope. Another principal receives not-found; revoked keys or permissions deny download. Re-export after expiry or restart. Multi-instance deployments need affinity to the issuing adapter or accept cache-miss/re-export behavior.

`POST /mcp/exports` and artifact downloads preserve the Origin allowlist and authenticated operation auditing, including correlation IDs with no raw diagram/arguments. Go's `GET /api/v1/agent/workspaces/{workspaceId}/scenes/{sceneId}/export-assets/{fileId}?assetId={uuid}` resolves authorized scene metadata, releases the workspace lock during bounded storage I/O, and rechecks authority and metadata after I/O. Storage reads use only server-owned bucket/key values and verify MIME, length and optional checksum. Neither the browser nor the agent supplies a storage URL. Reverse proxies must route the whole `/mcp` prefix, preserve Authorization, cap request bodies and omit query strings/credentials from logs.

## Verification

Tests cover real browser conversion and fonts, multilingual labels, official native parity, MIME/signatures, raster byte/dimension validation, source/node/edge/output bounds, network denial, expiry/principal isolation, and actual noncooperative worker/Chromium termination. The live Go + PostgreSQL + collaboration runtime + HTTP MCP test exercises export-only/read-only separation, all formats, remote forwarding, bearer downloads, scope removal and key revocation. Unit Go tests cover asset metadata/current-authority checks and bounded SDK object reads. KaTeX 0.18.2 hostile inherited-trust fixtures and normal Mermaid/math fixtures run in a real browser; see the dependency decision document and D4 report for exact commands and limitations. Container packaging and release acceptance belong to E2/E1; local tests do not assert a production rollout.


### D4 lifecycle correction

Review reproduced a browser-startup PID-reporting gap and leftover Playwright profile/artifact directories after normal success. The correction moves Chromium spawning into the parent: it owns the process handle immediately, assigns a private per-job profile/TMP directory, and passes only a generated loopback DevTools endpoint to the render child. The parent deadline covers startup and work, bounds graceful shutdown, kills noncooperative processes, reaps its children and removes that exact job directory before accepting another job. Regression tests cover stalled executable startup, child crash, repeated normal/error jobs, active Chromium loops, process/group exit and exact temporary-directory removal. Direct launch flags stay pinned to the installed Chromium/Playwright combination and require E2 nonroot-image verification.
